# Controlled deserialization-boundary experiment

## Research question

Given a controlled relevant-package mismatch, can strict Modelstamp loading reject
before a persisted object's reconstruction side effect occurs?

## Fixture

The experiment uses a deliberately controlled Python object whose reconstruction
creates a marker file in the CI runner's temporary directory. The marker is a
harmless observation mechanism; the fixture performs no network access, process
execution, privilege changes, or modification outside that marker.

The fixture is synthetic and its class module does not participate in Modelstamp's
automatic package-relevance mapping. RQ4 therefore controls relevance explicitly
rather than using this experiment to test relevance inference; that behavior is
evaluated separately by RQ1.

## Protocol

1. Persist the controlled fixture with Modelstamp/joblib.
2. Modify the actual `.manifest.json` sidecar used by Modelstamp.
3. Explicitly designate `joblib` as relevant and replace its recorded save-time
   version with the sentinel `0.0.0-controlled-drift`.
4. Call `modelstamp.check()` as a precondition and assert that it surfaces
   exactly the intended joblib mismatch.
5. Reset the marker and call
   `modelstamp.load(..., on_mismatch="raise")`.
6. Accept only `EnvironmentMismatchError` as the expected rejection and assert
   that the mismatch evidence names `joblib`.
7. Assert that the reconstruction marker has not been created.
8. Reset the marker, call direct `joblib.load()` on the same serialized
   artifact, and assert that reconstruction creates the marker.

The sentinel version is deliberately different from the installed joblib version,
so the experiment does not depend on a particular joblib release number.

## Scope

This experiment isolates reconstruction ordering **after a known relevant mismatch
has been established**. It is not evidence that Modelstamp automatically infers
joblib relevance for the synthetic fixture.

It is also **not** a malware-detection experiment and does not claim that
Modelstamp makes pickle/joblib safe for untrusted artifacts. It tests the narrower
boundary consequence: whether strict mismatch handling can reject the controlled
condition before the fixture's reconstruction side effect occurs.

Results are generated by execution and should not be inferred from this protocol
before execution.
